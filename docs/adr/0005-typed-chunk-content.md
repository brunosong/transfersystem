# ADR 0005. [도메인] 청크 내용을 Avro 타입으로 정의한다

- 상태: 채택
- 날짜: 2026-11-04
- 관련 문서: [이벤트와 메시지](../domain/events.md), [컨텍스트 맵](../domain/context-map.md), [ADR 0001](0001-message-contract-distribution.md)
- 관련 모듈: `infrastructure/message-contracts`, `CurriculumSourceConverter`, `CurriculumRepositoryImpl`

## 맥락

컨텍스트 맵은 저작 시스템과 배포 사이에 부패 방지 계층을 두고, 대상과는 공표된 언어로 이야기한다고 정했다. 그런데 메시지의 내용은 `jsonData: bytes`이고, 코드를 따라가 보면 이 결정이 내용에서는 지켜지지 않는다.

| 문제 | 근거 | 일어나는 일 |
|---|---|---|
| 원본 문서 모양이 대상까지 그대로 간다 | `CurriculumSourceConverter`: `subjectNode.set("subject", subject)` | 저작 문서의 필드 이름이 바뀌면 대상이 깨진다 |
| 레지스트리가 내용을 검사하지 못한다 | Avro 스키마에서 내용은 `bytes`다 | 봉투만 호환성을 검사한다. 내용이 깨지면 실행 중에야 드러난다 |
| 계약이 문서로 존재하지 않는다 | 에이전트가 `Document.getString("id")`로 꺼내고, 뼈대인지는 `curriculum` 키가 있는지로 짐작한다 | 서비스 팀이 자기 컨슈머를 만들려면 우리 코드를 읽어야 한다 |

마지막 문제는 [ADR 0002](0002-target-agent.md)의 목표와 부딪힌다. 에이전트를 떼어 내려면 서비스 팀이 계약만 읽고 컨슈머를 만들 수 있어야 한다.

## 선택지

| | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | 원본 JSON을 `bytes`로 그대로 싣는다 (지금) | 바꿀 것이 없다. 원본에 필드가 늘면 자동으로 실린다 | 위 문제 셋이 그대로다 |
| B | 우리가 정한 JSON을 `bytes`로 싣고 문서와 JSON Schema로 설명한다 | 원본과 분리된다. 스키마 변경 부담이 적다 | 검사를 따로 만들어야 하고, 문서와 실제가 어긋날 수 있다 |
| **C** | **Avro 타입으로 정의한다** | 레지스트리와 `test-compatibility`가 내용까지 검사한다. `.avsc`가 곧 계약 문서다. 대상이 쓰는 필드만 실린다. 뼈대와 과목을 타입으로 구별한다 | 필드를 더할 때마다 계약을 고쳐야 한다. 변환 코드가 는다 |

## 결정

**C를 쓴다.** `ApplyChunkCommand.content`는 `SkeletonContent` 또는 `SubjectContent`다. 필드는 [이벤트와 메시지](../domain/events.md#4-내용은-avro-타입으로-싣는다)에 있다.

내용은 이렇게 바뀌어 간다. 저작 문서의 모양을 아는 곳은 첫 단계 하나뿐이다.

```text
저작 문서 → (원본 컨텍스트의 ACL) → 커리큘럼 모델 → (배포가 나눔) → 청크 내용 → (messaging 모듈) → Avro
```

## 결과

### 얻은 것
- 저작 문서의 필드가 바뀌어도 고칠 곳은 변환기 하나다. 대상은 영향을 받지 않는다.
- 내용을 깨뜨리는 변경을 배포 전에 호환성 검사로 잡는다.
- 서비스 팀은 `.avsc`만 읽으면 된다.

### 감수한 것
- **원본에 필드가 늘어도 자동으로 실리지 않는다.** 대상에 보내려면 계약부터 고쳐야 한다. 번거롭지만 이것이 이 결정의 목적이다.
- **변환 코드가 는다.** 트리 필드가 많지 않아 감당할 수 있다고 본다.
- **지금 대상이 읽지 않는 원본 필드는 더 이상 나가지 않는다.** 나중에 쓰려면 계약을 고치고 재배포해야 한다.
- **새 내용 타입은 깨지는 변경이다.** 옛 소비자가 읽을 수 없으므로 새 스키마와 새 토픽으로 낸다.

## 실무에서는

이 결정은 실무 경험이 아니라, 에이전트를 떼어 낼 수 있어야 한다는 목표와 코드 확인에서 나왔다.

## 바꾸려면

**B로 바꾸기**: `content`를 `bytes`로 바꾸고 JSON Schema를 계약에 더한다. 필드가 자주 바뀌어 스키마 변경이 부담될 때 고려한다. 호환성 검사는 CI에 따로 만들어야 한다.
