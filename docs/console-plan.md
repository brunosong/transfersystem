# transfer-console 화면 기획

> 설계 의도와 고칠 목록은 [화면 설계](ui/screens.md)에 있다. 이 문서는 처음 기획, 와이어프레임, API 목록을 담고 있고 일부 말과 상태는 도메인 설계 이전의 것이다.
> 상태: 1단계(모의 모드 화면) 완료 (2026-11-03). 화면이 쓰는 API 모양은 `transfer-console/src/api/types.ts` 가 기준이다.
> 범위: 사가 이전 단계. **전송 하나 = 커리큘럼 하나를 대상 하나로 배포**하는 현재 구조를 기준으로 한다.
> 사가(두 대상 동시 반영, 보상)는 뒤로 미뤘다([ADR 0003](adr/0003-defer-saga.md)).

## 1. 무엇을 하는 서비스인가

**교육 콘텐츠 배포 시스템**이다. 콘텐츠를 만들어 두는 **원본 저장소**(Mongo)에서 커리큘럼을 꺼내, 학습자가 쓰는 **서비스 시스템**(MySQL)으로 배포한다.

```
[원본 저장소]  ──전송 요청──▶  transfer-service  ──Kafka(청크)──▶  data-migration-service  ──업서트──▶  [대상 시스템]
 Mongo 컬렉션                    청크로 나눔, 이력 기록                  대상 DB 선택, 저장                     온라인캠퍼스 / 부트캠프
                                                                                                             × PROD / DEV
```

| 개념 | 실제 데이터 | 설명 |
|---|---|---|
| 원본 저장소 | `sourceconfig` (transfer-service) | 읽어 올 DB 접속 정보와 컬렉션 |
| 콘텐츠 | 원본 컬렉션의 커리큘럼 문서 | 커리큘럼 → 학년 → 학기 → 과목 → 단원 → 차시 트리. 시드 기준 커리큘럼 하나에 차시 4,000개 |
| 대상 시스템 | `datamigrations` (data-migration-service) | 온라인캠퍼스·부트캠프 × PROD·DEV, 4개 |
| 전송(배포) | `transfer_log`, `transfer_chunk` | 커리큘럼 하나를 대상 하나로 보내는 작업 |
| 청크 | Kafka 메시지 하나 | 첫 청크는 커리큘럼·학년·학기 뼈대, 나머지는 과목마다 하나 (시드 기준 1 + 40개) |

### 사용자
**콘텐츠 운영자.** 하는 일은 셋이다.
1. 원본과 대상이 제대로 연결돼 있는지 관리한다.
2. 만든 커리큘럼을 골라 서비스에 배포한다.
3. 배포가 끝났는지, 대상에 원본과 똑같이 들어갔는지 확인하고, 실패하면 다시 보낸다.

### 화면 흐름
```
 설정                  고르기              보내기              지켜보기               확인
 ┌───────────┐       ┌──────────┐       ┌──────────┐       ┌──────────────┐       ┌──────────────┐
 │원본 저장소 │──┐    │ 콘텐츠   │──────▶│ 배포 요청 │──────▶│ 배포 상세     │──────▶│ 대상 데이터   │
 │대상 시스템 │──┴──▶ │ 탐색     │       │          │       │ (청크 진행)   │       │ 확인(원본 비교)│
 └───────────┘       └──────────┘       └──────────┘       └──────┬───────┘       └──────────────┘
                                                                   │ 실패
                                                                   ▼
                                                            실패 청크 재전송
 대시보드: 어디서든 진행 중·실패 건으로 바로 이동
```

## 2. 화면 목록

| # | 화면 | 경로 | 지금 상태 |
|---|---|---|---|
| 1 | 대시보드 | `/` | 없음 (지금 `/`는 전송 목록) |
| 2 | 원본 저장소 | `/settings/sources` | 없음 (새 전송 폼 안에 카드로만 있음) |
| 3 | 대상 시스템 | `/settings/targets` | 없음 (화면에 하드코딩) |
| 4 | 콘텐츠 탐색 | `/contents` | 없음 |
| 5 | 배포 요청 | `/deployments/new` | 있음 (원본 ID 직접 입력 방식) |
| 6 | 배포 이력 · 상세 | `/deployments`, `/deployments/:id` | 있음 (필터만, 검색·재전송 없음) |
| 7 | 대상 데이터 확인 | `/targets/:targetId/curriculums/:curriculumId` | 없음 |

메뉴: **대시보드 · 콘텐츠 · 배포 이력 · 설정(원본 저장소, 대상 시스템)**. 상단 오른쪽에 요청자 선택과 API 모드(실제/모의) 표시를 둔다.

화면에서는 "전송" 대신 **"배포"**라는 말을 쓴다. 운영자 입장에서 하는 일이 배포이기 때문이다. 코드와 API 이름(`transfer`)은 그대로 둔다.

## 3. 화면별 기획

### 3-1. 대시보드 `/`
처음 들어왔을 때 **지금 손봐야 할 것이 있는지** 바로 알게 한다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ 대시보드                                              [+ 새 배포]     │
├──────────────┬──────────────┬──────────────┬─────────────────────────┤
│ 오늘 배포  12 │ 진행 중   2  │ 실패      1  │ 연결 상태               │
│ 어제보다 +3   │              │ ▶ 확인하기   │ 원본 2/2 ● 대상 3/4 ●   │
├──────────────┴──────────────┴──────────────┴─────────────────────────┤
│ 확인이 필요한 배포                                                      │
│  ✕ CUR012 초등 교육 과정 12 → 부트캠프·PROD   청크 3/41 실패   10:42  ▶ │
├──────────────────────────────────────────────────────────────────────┤
│ 최근 배포                                                 [전체 보기]  │
│  ● CUR003 → 온라인캠퍼스·DEV   진행 중 ███████░░ 28/41   김운영  10:51 │
│  ✓ CUR001 → 온라인캠퍼스·PROD  완료    41/41            김운영  10:30 │
└──────────────────────────────────────────────────────────────────────┘
```
- 지표 카드를 누르면 배포 이력으로 가고, 그 상태 필터가 걸려 있다.
- 연결 상태는 원본·대상 연결 테스트 결과를 캐시해서 보여 준다. 끊긴 것이 있으면 빨간 점을 띄우고, 누르면 설정 화면으로 간다.
- 진행 중인 배포가 있으면 5초마다 갱신한다.

### 3-2. 원본 저장소 `/settings/sources`
콘텐츠를 읽어 올 곳을 관리한다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ 원본 저장소                                         [+ 원본 추가]     │
├──────┬──────────────┬───────┬──────────────────────┬────────┬────────┤
│ 이름  │ 콘텐츠 유형   │ DB    │ 위치                  │ 연결    │        │
├──────┼──────────────┼───────┼──────────────────────┼────────┼────────┤
│ 저작DB│ 커리큘럼      │ Mongo │ localhost:27017      │ ● 정상  │ 수정 ⋯ │
│      │              │       │ learningDB/Curricu…  │ 10:50  │        │
└──────┴──────────────┴───────┴──────────────────────┴────────┴────────┘
```
**추가·수정 (오른쪽 패널)**
- 입력: 이름, 콘텐츠 유형(처음엔 `커리큘럼`만), DB 종류(Mongo/MySQL), 호스트, 포트, DB, 사용자, 비밀번호, 컬렉션/테이블
- **[연결 테스트]**: 접속하고, 컬렉션이 있는지와 문서 수를 확인한다. 결과는 "연결됨 · 문서 300개"처럼 보여 준다.
- 저장은 연결 테스트를 안 해도 할 수 있다. 다만 실패했으면 경고를 띄운다.
- 비밀번호는 다시 보여 주지 않는다. 수정할 때 비워 두면 기존 값을 유지한다.
- 삭제: 이 원본으로 진행 중인 배포가 있으면 막는다. 이력이 있으면 소프트 삭제(비활성)한다.

### 3-3. 대상 시스템 `/settings/targets`
배포할 수 있는 곳과 그 상태를 본다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ 대상 시스템                                                            │
├──────────────┬───────┬──────────────────────┬──────────┬─────────────┤
│ 시스템        │ 환경   │ DB                   │ 연결      │ 배포 허용   │
├──────────────┼───────┼──────────────────────┼──────────┼─────────────┤
│ 온라인캠퍼스   │ PROD  │ mysql://…/onlinecamp │ ● 정상    │ [■ 켜짐]    │
│ 온라인캠퍼스   │ DEV   │ mysql://…/onlinecamp │ ● 정상    │ [■ 켜짐]    │
│ 부트캠프      │ PROD  │ mysql://…/bootcamp   │ ● 끊김    │ [□ 꺼짐]    │
│ 부트캠프      │ DEV   │ mysql://…/bootcamp   │ ● 정상    │ [■ 켜짐]    │
└──────────────┴───────┴──────────────────────┴──────────┴─────────────┘
```
- 접속 정보는 data-migration-service 설정 파일에 있다. 그래서 **처음엔 조회와 배포 허용 토글만** 한다. 화면에서 추가하거나 수정하지 않는다.
- 배포 허용이 꺼진 대상은 배포 요청 화면에서 고를 수 없다. 점검 중인 시스템을 막는 용도다.
- 행을 누르면 그 대상의 최근 배포 이력과 반영된 커리큘럼 목록이 나온다. 커리큘럼을 누르면 7번 화면으로 간다.

### 3-4. 콘텐츠 탐색 `/contents`
원본에 무엇이 있는지 보고, 배포할 커리큘럼을 고른다. **원본 ID를 외워서 입력할 필요가 없게** 하는 화면이다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ 콘텐츠   원본: [저작DB ▾]   [🔍 ID 또는 제목               ]           │
├───────────────────────────────┬──────────────────────────────────────┤
│ ID      제목            배포   │ CUR003  중등 교육 과정 3               │
│ CUR001  초등 교육 과정 1  ✓2곳 │ 학년 4 · 학기 8 · 과목 40 · 단원 200 · │
│ CUR002  중등 교육 과정 2  -    │ 차시 4,000   → 청크 41개로 나뉨         │
│▶CUR003  중등 교육 과정 3  ✓1곳 │                                      │
│ CUR004  고등 교육 과정 4  ✕    │ ▾ 중등 1학년                          │
│ …                             │   ▾ 1학기                             │
│                 [< 1 2 3 >]   │     ▸ 국어 (단원 5 · 차시 500)         │
│                               │     ▸ 수학 (단원 5 · 차시 500)         │
│                               │ 배포 현황                             │
│                               │  온라인캠퍼스·PROD ✓ 11/02 14:20       │
│                               │  온라인캠퍼스·DEV  - 배포 안 됨         │
│                               │                        [배포하기 ▶]   │
└───────────────────────────────┴──────────────────────────────────────┘
```
- 왼쪽: 커리큘럼 목록(페이지, 검색). "배포" 칸에는 대상 몇 곳에 배포됐는지와 마지막 배포 결과를 보여 준다.
- 오른쪽: 고른 커리큘럼의 요약 수치, 청크 수, 트리. 트리는 과목까지만 펼친다. 단원·차시는 수치로만 보여 준다(문서가 크다).
- 배포 현황은 대상 4곳 각각에 마지막으로 언제 배포했는지와 그 결과다.
- **[배포하기]**를 누르면 이 커리큘럼이 고른 상태로 5번 화면이 열린다.

### 3-5. 배포 요청 `/deployments/new`
무엇을 어디로 보낼지 정하고, 확인한 뒤 보낸다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ 새 배포                                                                │
│ ① 콘텐츠  ─────  ② 대상  ─────  ③ 확인                                  │
├──────────────────────────────────────────────────────────────────────┤
│ ① 원본 [저작DB ▾]  커리큘럼 [CUR003 중등 교육 과정 3      🔍]           │
│    과목 40 · 차시 4,000 · 청크 41개                                     │
│ ② 대상                                                                │
│    ( ) 온라인캠퍼스 · DEV                                               │
│    (●) 온라인캠퍼스 · PROD   ⚠ 운영 환경. 이미 배포됨(11/02) → 덮어씀     │
│    ( ) 부트캠프 · DEV                                                   │
│    ( ) 부트캠프 · PROD       배포 허용 꺼짐                              │
│ ③ 확인                                                                │
│    CUR003 을 온라인캠퍼스·PROD 로 배포합니다. 청크 41개.                   │
│    [ ] 운영 환경에 배포하는 것을 확인했습니다      (PROD 일 때만)          │
│                                       [취소]  [배포 요청 ▶]             │
└──────────────────────────────────────────────────────────────────────┘
```
- 커리큘럼은 검색해서 고른다. 4번 화면에서 왔으면 이미 골라져 있다.
- 대상은 **하나만** 고른다. 지금 API가 요청 하나에 대상 하나다. 여러 대상을 한 번에 보내는 것은 사가에서 다룬다.
- 대상마다 이 커리큘럼이 이미 배포됐는지 보여 준다. 배포된 곳이면 덮어쓴다(업서트)고 알린다.
- 같은 커리큘럼·대상으로 진행 중인 배포가 있으면 그 대상은 고를 수 없게 하고 "진행 중인 배포 보기" 링크를 단다.
- PROD로 보낼 때는 확인 체크를 해야 버튼이 켜진다.
- 요청에 성공하면 6번 상세 화면으로 넘어간다.

### 3-6. 배포 이력 · 상세 `/deployments`, `/deployments/:id`
**이력**
```
┌──────────────────────────────────────────────────────────────────────┐
│ 배포 이력                                                [+ 새 배포]  │
│ [전체 12][진행 중 2][완료 9][실패 1]   대상 [전체 ▾] 기간 [오늘 ▾]      │
│ [🔍 커리큘럼 ID]  요청자 [전체 ▾]                                       │
├───────┬──────────┬──────────────┬────────────┬───────┬───────────────┤
│ 상태   │ 커리큘럼   │ 대상          │ 진행        │ 요청자 │ 요청 시각      │
│ ● 진행 │ CUR003 … │ 온라인캠퍼스·DEV│ ██████░ 28/41│ 김운영 │ 11/03 10:51  │
│ ✕ 실패 │ CUR012 … │ 부트캠프·PROD  │ ██░░░░ 3/41 ✕1│ 이배포 │ 11/03 10:42  │
└───────┴──────────┴──────────────┴────────────┴───────┴───────────────┘
```
- 상태 필터에 대상, 기간, 커리큘럼 ID, 요청자 조건을 더한다.
- 상태는 운영자 말로 묶는다: **대기**(PENDING) · **진행 중**(SENT, PROCESSED) · **완료**(SUCCESS) · **실패**(FAILED).

**상세**
```
┌──────────────────────────────────────────────────────────────────────┐
│ ← 배포 이력   CUR012 초등 교육 과정 12 → 부트캠프·PROD      ✕ 실패      │
│ 요청 김운영 · 11/03 10:42   걸린 시간 12초   배포 ID a1b2…  [복사]        │
├──────────────────────────────────────────────────────────────────────┤
│ 진행  ██░░░░░░░░░░░░░  성공 3 · 실패 1 · 남음 37 / 41                    │
│ 청크  ■■■✕□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□                         │
│       0: 뼈대(학년·학기)  1~40: 과목     ← 칸에 마우스를 올리면 과목명·시각  │
├──────────────────────────────────────────────────────────────────────┤
│ 실패한 청크                                                            │
│  #3  중등 1학년 1학기 영어   Duplicate entry 'U0101031' for key …  10:42│
│                                        [실패 청크 다시 보내기]           │
├──────────────────────────────────────────────────────────────────────┤
│ [대상 데이터 확인 ▶]   [같은 내용으로 다시 배포]                          │
└──────────────────────────────────────────────────────────────────────┘
```
- 청크 칸마다 무엇이 들어 있는지(뼈대인지, 어느 과목인지)를 보여 준다. 운영자가 "영어가 안 들어갔다"고 알아볼 수 있게 한다.
- 실패한 청크는 대상이 돌려준 오류 메시지를 함께 보여 준다.
- **[실패 청크 다시 보내기]**: 실패한 청크만 새 아웃박스 메시지로 다시 보낸다. 청크마다 재시도 횟수를 남긴다.
- **[같은 내용으로 다시 배포]**: 원본을 다시 읽어 새 배포를 만든다. 5번 화면이 미리 채워진 상태로 열린다.
- 진행 중이면 3초마다 갱신하고, 끝나면 멈춘다.

### 3-7. 대상 데이터 확인 `/targets/:targetId/curriculums/:curriculumId`
배포가 끝났다고 데이터가 맞는 것은 아니다. **대상 DB에 실제로 들어간 것**을 원본과 나란히 놓고 본다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ CUR012 초등 교육 과정 12   대상: 부트캠프·PROD   마지막 배포 11/03 10:42 ✕ │
├──────────────────────────────────────────────────────────────────────┤
│           원본       대상       차이                                    │
│ 학년        4         4                                                │
│ 학기        8         8                                                │
│ 과목       40        39        -1  ⚠                                   │
│ 단원      200       195        -5  ⚠                                   │
│ 차시    4,000     3,900      -100  ⚠                                   │
├──────────────────────────────────────────────────────────────────────┤
│ [차이만 보기 ■]                                                        │
│ ▾ 초등 1학년 ▾ 1학기                                                   │
│     ✓ 국어   ✓ 수학   ✕ 영어 (대상에 없음)   ✓ 과학   ✓ 사회              │
│ 제목이 다른 항목 0건                                                    │
│                                    [이 커리큘럼 다시 배포 ▶]            │
└──────────────────────────────────────────────────────────────────────┘
```
- 수준별 개수를 비교하고, 과목 단위로 있고 없음을 표시한다.
- 비교는 ID 기준으로 한다. 같은 ID에 제목이 다르면 "변경됨"으로 표시한다(원본이 배포 뒤에 바뀐 경우).
- 이 화면은 "완료"인 배포에서도 쓸모 있다. 원본이 그 뒤로 바뀌었는지 확인할 수 있다.

### API 경로
- 화면은 두 서비스를 모두 부른다. 개발 서버와 nginx 프록시에서 `/api/v1/targets`는 data-migration-service로, 나머지 `/api`는 transfer-service로 넘긴다(`DATA_MIGRATION_SERVICE_URL` 추가).
- 배포 허용이 꺼진 대상으로 오는 요청은 transfer-service가 막는다. 그러려면 transfer-service가 대상 정보를 알아야 한다. 처음엔 data-migration-service를 조회하고, 나중에 이벤트로 캐시하는 방식을 검토한다.

### 저장소 변경
- `sourceconfig`: `name`, `enabled` 컬럼 추가. 시드의 `source_type` 값(`LEARNING_MATERIAL`, `USER_DATA`)이 enum(`CURRICULUM`, `EXAM_RESULT_DATA`)과 안 맞으니 맞춘다.
- `datamigrations`: `enabled` 컬럼 추가.
- `transfer_log`: 요청자, 대상 ID를 조회 조건으로 쓰므로 인덱스 추가.
- `transfer_chunk`: `label`(뼈대 / 과목명), `error_message`, `retry_count` 추가.

## 5. 하지 않는 것 (이번 범위 밖)
- **여러 대상 동시 배포, 보상(되돌리기)**: 사가를 구현하게 되면 다룬다([ADR 0003](adr/0003-defer-saga.md)). 이번 화면은 대상 하나 기준이다.
- **시험 결과(`EXAM_RESULT_DATA`) 배포**: 콘텐츠 유형 선택지에만 "준비 중"으로 남긴다.
- **로그인·권한**: 상단에서 요청자 이름을 고르는 정도만 한다. 브라우저에 저장하고 요청 헤더로 보낸다.
- **대상 접속 정보 편집**: 설정 파일로 관리한다. 화면은 조회만 한다.
- **예약 배포, 승인 절차**: 필요해지면 그때 기획한다.

## 6. 진행 순서

**1단계. 모의 모드로 화면 7개**
- 모의 데이터: 원본 저장소 2개, 커리큘럼 30개(시드 생성기와 같은 ID 규칙), 대상 4개(부트캠프·PROD는 끊김 상태), 배포 이력 20건(실패 포함)
- 모의 배포는 시간에 따라 청크가 진행된다. 커리큘럼 ID에 `fail`이 들어가면 일부 청크가 실패하고, 재전송하면 성공한다.
- 대상 데이터 확인은 모의 배포 결과로 만든다. 실패한 과목은 대상에 없다.
- 지금 있는 목록·상세·새 전송 화면은 이 구조로 옮기고, 사가 전용 표시(단계 타임라인)는 뺀다.
- 끝나면 직접 눌러 보며 흐름을 다듬는다.

**2단계. 백엔드 API (화면이 정한 모양대로)**
1. 원본 조회: 커리큘럼 목록·트리, 연결 테스트 → 4, 5번이 실제 데이터로 돎
2. 대상 목록·연결 테스트 → 3번, 하드코딩 제거
3. 배포 요청 보강: 요청자, 409, 청크 라벨과 실패 메시지 → 5, 6번
4. 원본 저장소 CRUD → 2번
5. 대상 데이터 조회 → 7번 (Phase 1의 "Bootcamp 저장 실제 구현"이 먼저 필요)
6. 실패 청크 재전송 → 6번

**3단계. 로컬 E2E**
Phase 2의 docker-compose 환경에서 처음부터 끝까지 한 번 돌린다. 원본 등록 → 연결 테스트 → 커리큘럼 고르기 → DEV 배포 → 완료 확인 → 대상 데이터가 원본과 같은지 확인.

## 7. 정해야 할 것
1. **대상 정보를 transfer-service가 어떻게 알게 할지**: 매번 data-migration-service를 조회할지, 이벤트로 받아 캐시할지. 제안: 처음엔 조회로 시작한다.
2. **원본 비밀번호 저장**: 지금은 평문이다. 제안: 이번에는 응답에서 빼는 것만 하고, 암호화는 Phase 5의 Secret 정리와 함께 한다.
3. **재전송 단위**: 실패한 청크만 다시 보낼지, 배포 전체를 새로 만들지. 제안: 둘 다 제공한다(상세 화면의 버튼 두 개).
